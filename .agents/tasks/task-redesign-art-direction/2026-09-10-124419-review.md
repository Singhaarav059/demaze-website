# Art-direction reconciliation + polish pass for the DEMAze site

This change adapts a single strong idea from the origin/test handoff (contain-fitting the pinned service illustrations) and otherwise refines `main`'s existing motion system with a full art-direction pass: image fitting/positioning, spacing rhythm, typography hierarchy, grid column ratios, wash-tint balancing, and easing harmonization onto the shared `var(--ease-out)` token. Two concrete vibe-coded defects are fixed — an invalid empty `content:` separator on the mobile industries list (now a middot) and `object-fit: cover` cropping the four differently-shaped service illustrations (now `contain`). The `/projects` editorial wall grows its `SPANS` array from 8 to 16 entries and gains `grid-auto-flow: dense` so the asymmetric tiles pack without gaps. Content is untouched: `site-data.ts` and the generated `images.ts` show a literal zero-line diff, so all counts guarded by `site-data.test.ts` are preserved by construction.

Watch for: nothing blocking. One cosmetic comment inaccuracy in the showcase-caption heading rule (confidence: confirmed) and the usual caveat that dense packing can reorder decorative tiles (confidence: confirmed, and intended). All correctness-by-construction checks pass; the CI gate and a reduced-motion device pass remain deferred to CI/preview per the environment constraint.

**Verdict**: APPROVED

## High-level view

The image-fitting work is the heart of the change. The pinned-services panel moves from `cover` to `contain` with a symmetric 7% inset so the four illustrations (937x400, 422x400, 512x400, 1114x424) sit whole and centered instead of each cropping differently; the JS crossfade only ever writes `opacity`, so switching the fitting mode can't disturb it. The `/projects` and homepage teaser screenshots gain `object-position: center top` so UI headers stay in frame, and the showcase parallax keeps a 116%-tall image drifting within a range that never exposes a gap. The about split pins a 4/3 ratio so its 533x403 image stops stretching against a center-aligned row.

The layout system is unified around two column-ratio families — balanced asymmetry (0.85/1.15: hero, about, contact) and heading-left (0.8/1.2: founder story, FAQ) — replacing several one-off ratios. Card padding converges on `1.25rem` across the service/contact/options families, and three sub-card headings are pulled toward one treatment. Page titles drop a bespoke clamp to inherit the shared `--display-xl`, so page H1s match the hero scale rather than running slightly larger.

The wash chapters are re-tinted toward a common ~55% so no chapter reads more saturated than its neighbor, with mint nudged to 58% as the lightest hue. Every ad-hoc `ease`/`cubic-bezier(...)` transition is swapped to `var(--ease-out)` for one easing voice. None of these touch the reduced-motion or width gates, so mobile and reduced-motion behavior is unchanged.

The known gaps are all deferred verification, not defects: typecheck/lint/test/build and the scroll-smoothness + `prefers-reduced-motion` device pass can't run in this network-isolated sandbox and are owed to CI/preview.

### Pinned-services fitting switch is safe against the crossfade

The panel `img` goes from `inset:0; width/height:100%; object-fit:cover` to `inset:7%; width:86%; height:86%; object-fit:contain; object-position:center`. The four illustrations span aspect ratios from 1.05:1 to 2.6:1, so `cover` zoomed and cropped each one differently — the defect called out in `findings.md`.

`pinned-services-showcase.tsx` writes only `img.style.opacity` in its `paint()` loop and an inline `opacity` on initial render; it never sets `inset`, `width`, `height`, `object-fit`, or `transform`. The `{...service.image}` spread puts intrinsic `width`/`height` attributes on the element, but the CSS percentage rules win for layout. So the crossfade opacity math is untouched by the fitting change. (confidence: confirmed)

### Projects wall: dense packing + 16-entry SPANS

`SPANS` grows to 16 with 2x2 tiles at indices 0, 6, 9, 14 and 1x1 everywhere else, and the grid gains `grid-auto-flow: dense` over its 4-column / 220px-row track. Dense lets the 1x1 tiles backfill the holes a 2x2 leaves at a row end, keeping the wall gap-free wherever the large spans land. The tradeoff — dense may hoist a later small tile into an earlier hole, so visual order can diverge from source order — is acceptable for a decorative wall and the numbered captions (`String(i+1).padStart(2,"0")`) still label each project.

Indexing stays `SPANS[i % SPANS.length]`, so a project-count change degrades gracefully rather than throwing. At `<=900px` the grid drops to 2 columns and `.project-showcase-card { grid-area: auto !important }` neutralizes both the spans and dense flow, so the mobile variant is a plain 2-col wrap — the comment's claim that dense is harmless there is correct. (confidence: confirmed)

### Screenshot crop anchoring and parallax buffer

Both the homepage `.project-image img` and the showcase card gain `object-position: center top` so UI screenshots keep their headers in frame instead of centering into the middle of the interface. The showcase image is `height:116%` at a base `top:-8%`; the parallax loop sets `top = -8 + (p-0.5)*10` where `p ∈ [0,1]`, giving a `top` range of −13% to −3%. At the shallow end (`top:-3%`) the image bottom reaches 113%, at the deep end (`top:-13%`) it reaches 103% — both still cover the 100% box, so the drift never exposes a gap. The comment's "8% buffer at both edges" describes the static center only; the live minimum buffer is ~3%, still safe. The parallax loop early-returns under `prefers-reduced-motion`, so this is desktop-motion only. (confidence: confirmed)

### Column-ratio and padding unification

Column ratios collapse into two named families: balanced asymmetry `minmax(0,0.85fr)/minmax(0,1.15fr)` for hero/about/contact, and heading-left `0.8/1.2` for founder story and FAQ (the FAQ and about-split also gain `minmax(0, …)` guards that prevent their content columns from blowing out on overflow). Card padding converges on `1.25rem` for the service card, contact options, and the service-card index badge offsets move to match. The about split additionally pins `aspect-ratio:4/3; height:auto; object-fit:cover` so its 533x403 image no longer stretches against the row's `align-items:center`. The founder portrait keeps `align-items:stretch` + `object-fit:cover` and only widens its column, so its fitting is unchanged. (confidence: confirmed)

### Page-title scale and tint/easing harmonization

`.page-intro h1` drops its bespoke `clamp(2.4rem,4vw,4rem)` so it inherits the shared H1 rule's `var(--display-xl)` (max 3.5rem). Because `.page-intro h1` is declared after the shared selector and only sets `max-width`, the inherited `font` shorthand applies cleanly — page titles now match the hero scale instead of running larger. The wash chapters re-tint toward ~55% (mint to 58% as the lightest hue), and every ad-hoc `ease`/inline `cubic-bezier(...)` transition is replaced with `var(--ease-out)` (`cubic-bezier(0.22,1,0.36,1)`), giving one easing voice without touching durations. (confidence: confirmed)

### Industries separator defect fix

The mobile industries separator `content: ;` (invalid empty value, which drops the whole `::after` rule) becomes `content: "\00B7"` with a `0.3rem` left margin and muted color, so the inline-flowed solution list reads as `A · B · C` rather than words butting together on a `0 0.3rem` gap. (confidence: confirmed)
