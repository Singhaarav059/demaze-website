# Full-site pink redesign ported into the App Router (v1)

The static prototype for the Demaze site was ported into the Next 16 App Router across four commits: a foundation pass (fonts, oklch tokens, chrome, Nav/Footer, a single motion controller) and three page passes (home, projects/services, about/contact). The approach keeps pages as server components and concentrates every scroll-driven behaviour in one client `SiteMotion` controller that binds to declarative `data-*` hooks, so the pages stay static markup that renders fully without JavaScript. Missing prototype assets (studio video, project/service/tech imagery, about/founder/footer stills) were deliberately replaced with CSS-gradient tints, inline SVG and text placeholders rather than dead `src`s. The copy gate passes and the service-card deep-link ids survive.

Watch for: the home hero `<video>` autoplays unconditionally and is never paused under `prefers-reduced-motion` (**confirmed**), which is the one real accessibility gap in an otherwise reduced-motion-safe change. Everything else is fidelity/adaptation detail.

**Verdict**: NEEDS_CHANGES

## High-level view

The motion architecture is the load-bearing decision. `MotionControl` was replaced by `SiteMotion`, a single client component mounted once in the layout that owns the scroll listener, the header `[data-scrolled]` state, reveal-on-scroll, metric count-up, hero/image parallax and the services sticky-stage. It re-binds per route via `usePathname`, throttles with rAF and passive listeners, and gates everything behind `html[data-js]`. The pages themselves stay server components emitting the `data-reveal` / `data-metric` / `data-hero-frame` / `#services-stage` / `data-parallax-img` / `#scroll-progress` hooks the controller expects — the markup and the hook contract line up on every page.

No-JS and reduced-motion are handled as first-class states, not afterthoughts. Content is visible by default; the hidden pre-reveal state only applies under `html[data-js]`, a 1500ms safety timeout force-reveals anything the observer misses, and reduced motion shows everything immediately with instant count-up. The one exception is the native hero video, which sits outside this system and autoplays regardless of the reduced-motion preference.

The typography contract is met exactly: DM Sans drives body/UI, Space Grotesk drives every heading, the metric values and both founder quotes. The asset gap is handled by substitution — every remaining `src` in the tree points to a file that exists (`hero-transform.mp4`, `demaze-logo.png`, `krupal-chaudhary.jpg`), and decorative placeholders are `aria-hidden` with real stats/copy carried as text. Service-card ids `ai-ml` / `web-mobile-saas` / `ecommerce` / `cloud` are preserved for `/services#<key>`, and the copy gate passes with no em dashes, including the restructured About "who we are" paragraph.

### Motion controller and the hook contract

The effects are keyed on `usePathname` because the layout persists across client navigation — re-querying the DOM per route is what keeps the observed element set fresh rather than stale from the first page. The hook contract matches the markup on every page: home emits `data-hero-frame` on the video frame, `data-metric` with `data-target/data-prefix/data-suffix` on each metric cell, `#services-stage` containing `[data-service-row]` and `[data-service-img]` indexed `0..3`, and `data-reveal` throughout; projects emits `data-parallax-img` on each bento tile; the layout carries `#scroll-progress`. The sticky-stage focus picks exactly one active image via a lerped nearest-to-centre score and toggles `data-active`/`data-focused`, with indices aligned to the `homeServiceRows` order.

One count-up format edge case: the `$10M+` metric carries its `$` in `data-prefix` and `M+` in `data-suffix` over `value=10`, so the animation reads `$0M+ … $10M+`. Final value and SSR fallback are correct; the mid-animation `$0M+` is a cosmetic quirk to be aware of if the count-up is reused for other currency figures.

### Reduced-motion and no-JS safety, and the one gap

`[data-reveal]` elements only get the hidden pre-reveal state under `html[data-js]`; without JS they render at full opacity. Under `prefers-reduced-motion` the controller reveals everything synchronously, fills metrics to their final value, focuses the first service row/image, and never starts the rAF loop; the CSS independently neutralises the reveal transition, hides the scroll-progress bar and stops the marquee/eyebrow animations. The 1500ms safety timeout means a missed IntersectionObserver entry can't leave content permanently hidden.

The gap is the home hero video. It is a native `<video autoPlay loop muted playsInline>` that lives entirely outside the motion controller, so it autoplays for every visitor including those who asked for reduced motion. `muted playsInline` satisfies autoplay policies but not the accessibility preference. It also has no `poster`, so there's no defined first-frame for the pre-load / no-JS state. Gating autoplay on the reduced-motion query (the controller already tracks it) or dropping `autoPlay` in favour of a play affordance, plus a `poster`, would close this.

```
prefers-reduced-motion: reduce
  ├─ reveals            → shown immediately            ✓
  ├─ metric count-up    → instant final value          ✓
  ├─ services stage     → first row/img focused         ✓
  ├─ scroll-progress    → display:none                  ✓
  ├─ marquee / eyebrow  → animation:none                ✓
  └─ hero <video>       → still autoplays + loops        ✗
```

### Server/client split and Next 16 usage

Only the three components that need browser APIs are client (`Nav` for `usePathname`, `ContactForm` for form state, `SiteMotion` for scroll); the five pages stay server components exporting static `metadata` via the shared `pageMeta` helper. Accessibility of the image treatment is worth calling out because it's easy to get wrong under an asset substitution: the About who-we-are photo is `alt=""`/`aria-hidden` (decorative), while the founder-quote photo carries a descriptive alt and the logo `alt="Demaze"` is meaningful. Active links get `aria-current="page"` from `usePathname`. Fonts are exposed as CSS variables mapped in the `@theme` block so components reference `--font-dm-sans` / `--font-space-grotesk` without importing the font objects.

### Contact form degradation

The form previews a mailto draft client-side and never posts to an endpoint, which the copy states plainly. The submit button is `disabled={!isHydrated}`, so before hydration it is inert; the `<noscript>` block covers scripts-off with a direct mailto. The uncovered window is JS-enabled-but-not-yet-hydrated (or a hydration error): a visitor could fill the form and find submit dead with no native fallback, since the `onSubmit` handler is what builds the draft. Given the form has no server endpoint by design this is a minor risk, but worth an explicit decision rather than an accident of the hydration gate.

### Asset substitution and dead-src avoidance

Every `src` that ships points to a real file: the hero video, the logo, and the founder photo (`/krupal-chaudhary.jpg`, reused for the About media and both founder quotes). Project tiles, service-card media, tech marquees and the footer mark are CSS-gradient tints, inline SVG or text — no `<img>`/`<video>`/`url()` references a missing prototype asset, so nothing 404s. Decorative placeholders are `aria-hidden` while the real information (stats, tech names, industry names) is present as text, including `visually-hidden` lists that name the marquee technologies for screen readers.

### Copy gate and the About restructure

`node scripts/check-copy.mjs src` passes (32 files) and a direct scan for U+2014 across `src` and `README.md` finds nothing. The prototype's About "who we are" sentence that joined two clauses with an em dash is restructured with a comma in `about.ts`, keeping the meaning while staying gate-clean; the reasoning is documented inline next to the string.

### Services page deep-links and the industries swap

The four service cards render with `id={category.key}` in source order, preserving `ai-ml` / `web-mobile-saas` / `ecommerce` / `cloud` for `/services#<key>` fragment navigation. One fragility sits in the industries grid: it takes the first seven names straight from `industries.ts` and hardcodes "Real Estate" as the eighth to match the prototype, then looks each name up in a descriptor map. If `industries.ts` is ever reordered so a different name lands in the first seven, its descriptor falls through to `""` silently. Driving the eighth slot from content, or asserting the expected names, would make that coupling explicit rather than positional.
